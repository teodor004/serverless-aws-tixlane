## How to mark a row verified

1. Open the source and check the claim against the version you are about to pin.
2. Replace the `verified?` cell with `Yes — YYYY-MM-DD, <version seen>`, and put the exact
   page or release link in `source URL`.
3. If the claim was wrong, set the cell to `Corrected — YYYY-MM-DD`, fix the code in the
   same change, and describe the difference in `note`.
4. For pinned versions, update `versions.env` / `.tflint.hcl` / the workflow SHA in the same
   commit. `make verify` (scripts/check_versions.sh, scripts/check_action_pins.sh) fails while
   any `PIN_ME` or tag-only `uses:` remains.

Code that depends on a row with `No` is **not yet trusted**: do not treat a green local run
as evidence for that row until the row itself is checked.
